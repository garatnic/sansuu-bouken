# キャラクター適性スコア：理論採点仕様 v1

作成：2026-10-28。対象：GitHub main ver.74、927体、67スキル。**本書の点数は採点モデルの暫定設計値であり、ゲーム仕様上の数値・実測成果ではない。** Phase 4～6の独立実測により検証・調整する。ゲーム本体への反映は別途承認。

## 1. 定義と算出式
各キャラクターの「開拓／仲間／お宝／探索」を**それぞれ独立した0～100点**とする。合計100制約なし。職業(job)や入手レアリティ、過去のキャラ割当時の評価点は用いない。各スキルのLvに応じた表の基礎寄与点を対応する4分野に配分する。表の「配分比率」は**開拓／仲間／お宝／探索**の順（合計100）。

スキルi、Lv l、分野kの基礎寄与は `base_i(l) × share_i(k)/100`。キャラクターの分野kの未正規化点は `raw_k = Σ_i base_i(l_i) × share_i(k)/100 + synergy_k`。スコアは `round(100 × (1 - exp(-max(0,raw_k)/35)))` を0～100に制限する。丸めはJavaScriptの`Math.round`。この式は単一強スキルだけで100にならず、複数スキルで漸減する設計上の尺度であり、正答率・成功確率ではない。正規化係数35はv1仮置きで、後の実測で改訂可能。

## 3. 相乗・競合・支援の扱い
1. **単体の採点**：同一キャラの保有スキルだけを評価。複数キャラ間のLv合算・重複上限は**個人点へ適用しない**。編成時の有効Lvは別途`min(3, ΣLv)`で計算する。個人の同一ID重複は不許可。
2. **個人内シナジー**：A04～A10と対応するE01～E07が同一キャラにある場合、開拓rawに`+min(6, 2×min(A_Lv,E_Lv))`。ただし現行個人構成では同じキャラにA特攻とE加護の共存が可能な場合のみ。B02とC01、B03とD01、F01とC04、F02とD05の共存は対象に対応する分野rawへ`+2`。同一キャラに実在する組合せのみ適用する。
3. **相乗の上限**：全シナジー加算は各分野`max 8 raw`、各組合せの加点は一度。上記にない組合せの推測加点は0とする。これらはゲーム内で発動率が上がるという意味ではない。
4. **環境支援**：E01～E07は開拓55%・探索45%、E08は開拓35%・探索65%へ配分。地形加護は単体の開拓を直接増やすとは限らないが、パーティーの地形特攻を支援し得る価値を0にしない。D06は仲間分野に分類し、編成全員の所属グループを使う本来の実効は編成評価で別計算する。
5. **競合**：C01/D01はイベント抽選枠で競合し、F03はC02/D02と成功重みを合算。C04と分類C05～28は抽選重みを乗算、D05とD06は同一の元重みを使う。これらの**他キャラとの相互作用を個人点から差し引かない**。Phase 4の補助試験では組合せごとの実効差を記録する。
6. **条件依存**：A12は終盤、A11は開始時、A02は隣接未開拓の枯渇、A03は累計閾値、B系は公開情報に基づく行動、C04/C05～28/D05/F01/F02は所持進行と候補集合、D03/D08/D09は地図サイズと最低保証に依存。基礎点は標準10×10・30問・収集途中の想定。状況が変わっても**個人マスタの適性点は変動させない**。
7. **D04**：実装されていないため全Lvの基礎寄与0。将来の実装時には新しい採点仕様バージョンで再評価する。E09は対象外。

## 4. 再現性・検証・記録
- 入力：`data/characters.json`の927体のID・skills（ID/Lv）、`data/skills.json`の67ID。入力データを改変しない。
- 出力：各キャラID、`aptitudeVersion: \"1.0.0-draft\"`、`scores:{development,companions,treasure,exploration}`、`raw`、スキルごとの基礎寄与、シナジー内訳、採点条件タグ。小数計算の途中は丸めず、最終スコアだけ整数。
- 検証：全927件、ID一意、スキルID/Lv有効、各点0～100、D04のみキャラが持つ場合は0、4分野を足して100にしない、同一入力で同一出力、入力順の影響なし。スキル欠損・不明IDはエラー（黙って0点にしない）。
- 実測：Phase 4の50体×100冒険、支援系は固定パートナー比較。実測の新規品・新規仲間は所持状態に左右されるので条件固定。実測との相関・順位逆転・外れ値をPhase 5で検証し、v2へ改訂可能。
- 限界：本v1の配点は定量実測から回帰した係数ではない。支援価値は暫定的な専門家判断。0点は当該分野へのモデル上の寄与なしで、ゲーム内で絶対に役立たないことを意味しない。
