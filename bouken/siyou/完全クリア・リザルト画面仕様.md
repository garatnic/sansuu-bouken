## 1. 背景と目的

算数ぼうけんは、四則演算を繰り返し解きながら世界を開拓し、施設を訪ね、仲間やお宝に出会うゲームである。マップを最後まで遊び切った達成感を可視化するため、**完全クリア時に自動で表示するリザルト画面**を追加する。

目的は、スキルを細かく採点することではなく、**「今回の冒険で何を達成し、何に出会ったか」を子どもが楽しく振り返ること**。数字の小さなインフレ（自動開拓や博物館ボーナスも含む）を楽しめるようにし、仲間・お宝の成功も失敗も「冒険の思い出」として残す。

## 2. 検討経緯・設計判断

1. 最初は、算数の成績、開拓、施設、仲間、お宝、スキル発動など広く候補を出した。
2. **全域開拓**と**完全クリア**を区別した。通常は施設を未訪問のまま全マス開拓することは想定しにくいが、例外に備えてリザルトの表示条件は**完全クリアのみ**とする。全域開拓報酬の付与タイミングを変更する趣旨ではない。
3. リザルトは完全クリア時に**自動表示**。最上部に大きく「**おめでとう！**」を掲げる。
4. 当初はスキルを持つ仲間の活躍を表示する案も検討したが、合算スキルや成果に直結しない効果があるため、**スキル一覧からリザルト項目を逆算する設計は取りやめた**。表示するのは、プレイヤーに分かりやすく、実際の成果として計測できる項目に限定する。
5. 仲間・お宝を別々の欄にする案も取りやめ、**仲間・お宝・クリア報酬をひとつのカード内に混在させ、実際に出会った順に並べる**ことにした。失敗も残す。
6. 正解率は、誤答後に同じ問題を解き直すゲーム仕様を踏まえ、**初回回答の正解率**とする。
7. リザルトは**直近1回のみ保存**し、ホームの「**記録・実績**」から再表示できるようにする。
8. クリアタイムは壁時計上の経過時間ではなく、**冒険画面を開いている時間の累計**。操作しない放置時間も含め、ホームなど冒険以外の画面・バックグラウンド・終了中は含めない。
9. 開拓実績は**自力開拓／自動開拓**の2分類とする。冒険開始時にスキルで開いているマスも自動開拓。
10. **完全クリア報酬を受け取った後**にリザルトを表示する。仲間とお宝にはどちらも獲得失敗がある。
11. 旧データは現時点でプレイヤーがいないため、互換性維持を必須条件としない。必要なら初期化または次の冒険から計測開始してよい。

## 3. 確定した機能要件

### 3.1 発火条件・表示

- マップの**完全クリア**成立時に、リザルト画面を自動表示する。
- 「全マス開拓済みだが未訪問施設がある」場合はリザルトを表示しない。施設訪問を終えて完全クリアとなった時点で表示する。
- 冒頭には大きく「おめでとう！」、続けて「マップかんぜんクリア！」等の祝福表現を配置する。
- 同じ完全クリアで重複表示・重複記録しないようにする。画面を再読込しても二重計上しない。
- 既存の全域開拓報酬の獲得条件やタイミングを不必要に変更しない。

### 3.2 リザルトの情報構成

スマートフォンで縦スクロールする一画面を基本とし、次の順序を推奨する。

1. **祝福ヘッダー**：「おめでとう！」／完全クリア。
2. **ぼうけんした世界**：ミニマップ、マップサイズ、開拓の成果、クリアタイム。
3. **算数のきろく**：解いた問題数、初回正解率、最大連続正解、四則演算別成績。
4. **ぼうけんの思い出**：仲間・お宝・クリア報酬の画像を、種類を分けず出会った順に表示する**単一のカード**。
5. **操作部**：既存の画面導線に整合する戻り操作。

この順序は推奨レイアウト。各カードの寸法、文字、配色、細かなボタン配置は既存UIに合わせて調整してよい。

### 3.3 算数の記録

- **解いた問題数**：今回の冒険中に最終的に正解して完了した問題の数。誤答による再挑戦は新しい問題として数えない。
- **初回正解率**：初回回答で正解した問題数 ÷ 完了した問題数 × 100%。分母0の場合は `—` 等を表示し、0%と誤認させない。
- **最大連続正解**：各問題の**最初の回答**で正解した連続数の最大値。初回誤答で連続が途切れる。これは初回正解率との一貫性を優先する実装上の提案であり、既存仕様との衝突があれば報告する。
- **四則演算別成績**：足し算・引き算・掛け算・割り算ごとに問題数と初回正解率等を表示。未出題の演算は `—` 等とする。
- 問題を何度か間違えてから正解した場合、最終正解によって初回正解扱いに書き換えない。

### 3.4 開拓・施設の記録

- 開拓実績は**「自力開拓」と「自動開拓」の2種類**で表示する。従来案の「通常／追加／その他」の3分類は**廃止**する。
- **自力開拓**：算数に正解して、基本効果の「1問につき1マス」で実際に開いたマス。問題完了数と一致する可能性が高いが、例外の有無は現行処理で確認する。
- **自動開拓**：自力開拓以外の効果で実際に開いたマス。スキルによる追加開拓、**冒険開始時にスキルの効果で開いているマス**、博物館ボーナスなどを含める。原因別に第三の開拓区分を設けない。
- マップの初期状態に元々存在する開始地点などをどう数えるかは、**「スキルで開いたマス」と区別して**現行コードを調査する。初期配置の開始地点を無条件に自動開拓へ加算しない。
- 同一マスを重複して開拓実績に加算しない。自力＋自動は実際に新しく開いたマスの合計に整合させる。
- **透視マス数**は実際に新しく可視化したマスを計測する候補として採用する。透視は開拓とは異なる指標であり、自力／自動の開拓数へ混ぜない。
- **訪問した施設数**を表示する。施設訪問の重複計上を防ぐ。
- スキル別発動回数や仲間別貢献度・MVPは必須要件ではない。**スキル一覧を起点にリザルト項目を増やさない**。

### 3.5 ミニマップ

- **クリアした実際のマップ**を小さく描画する。
- **1マス約5ピクセルは初期アイデアであり固定仕様ではない**。10×10と30×30でセルサイズを変えてよい。見やすさを優先し、実装しながら調整する。
- 地形を識別できる色で表示し、**施設は赤い点などの明瞭な記号**で重ねる。
- 完全クリア時の地形・施設配置を再表示時にも再現できるよう、直近リザルトに必要な地図情報を保持する。
- レイアウト上の拡大縮小は可能だが、マップの縦横比は保持する。

### 3.6 「ぼうけんの思い出」カード

- **仲間・お宝・クリア報酬を一つの画像グリッドに混在**させる。カテゴリー別の別カードにはしない。
- **冒険中に出会った順**で表示する。クリア報酬は実際に受け取った時点の順序で含める。
- **仲間・お宝の双方に獲得成功・失敗がある**。成功・失敗の両方を記録し、失敗した画像は**グレースケール＋赤い×印**を重ねる。
- **初獲得**には**王冠マーク**を付ける。仲間・お宝は破棄できないゲーム仕様のため、過去に獲得済みかを既存の獲得・所持情報から判断する（具体的な参照先はWorkが確認）。
- 同じ仲間・お宝が複数回出た場合も**出現回数分**を並べ、成功／失敗の結果をそれぞれ残す。
- 全域開拓で獲得した仲間などの**クリア報酬も獲得した仲間に含める**。ただし施設での加入試行の成功率を計算する場合、加入試行を伴わない確定報酬を分母に混ぜない。
- 仲間・お宝の獲得数／失敗数など、理解しやすい集計値はカード内に添えてよい。
- 画像は既存のゲームアセットを使い、失敗状態でも元の対象が分かるようにする。王冠・赤い×が重なる場合は視認性を優先する。
- イベント履歴は**プレイヤーが出会った順**で記録し、現在の所持品一覧から後で推測して復元しない。記録する内部処理の瞬間は、表示順と結果が変わらない限り実装裁量。同一イベントで複数対象が出る場合は既存の画面表示順を優先する。

### 3.7 クリアタイム

- 冒険開始時に計測を開始し、**完全クリア時に停止**する。
- **冒険画面が前面で表示されている時間の累計**を採用する。操作していない放置時間も含む。冒険中の施設イベントなど、冒険画面内の操作は計測対象とする。
- アプリ／タブを閉じている間、別アプリへの切替・バックグラウンドの間、**ホーム画面や「記録・実績」など冒険以外の画面へ移動している間**は計測しない。
- 再開時は保存済み累計に加算し、ページ再読込・日をまたいだ再開でも継続する。
- 表示例：`1時間23分45秒`。必要に応じて時間未満は `12分34秒` など自然に表示する。
- 二重加算やバックグラウンド滞在時間の混入を避けるため、表示状態変更・画面遷移・保存・復帰を考慮する。

### 3.8 保存・再表示

- **直近1回の完全クリアリザルト**を保存する。新しい完全クリアで上書きする。
- ホームの**「記録・実績」**から、その直近リザルトを閲覧できるようにする。
- 保存対象は数値のほか、イベント順序、獲得成否、初獲得フラグ、表示に必要な対象ID、ミニマップ再現情報、クリアタイムなど。
- 未クリアの進行中データと直近の完了済みリザルトは別扱いとし、新しい冒険を開始しただけで直近リザルトを消さない。
- **旧セーブとの互換性は必須ではない**（現時点でプレイヤーがいないため）。必要に応じてセーブ初期化、または次の冒険から新規計測を開始してよい。移行しない過去データを推測して補完しない。どちらを採用するかはWorkが事前報告する。

## 4. 未確定事項とWorkへの判断委任範囲

以下は**企画上の決定ではない**。既存実装を調べて整合的な案を選び、重要な分岐は実装前にユーザーへ確認すること。

- **表示順序**：完全クリア報酬の受領処理が終わった**後**にリザルトを自動表示する（確定）。報酬演出・既存モーダルとの接続は調査して整合させる。
- **リザルトを閉じた後の遷移先・ボタン**：前案の「ホームにもどる／つぎのぼうけん」は提案にすぎず、ユーザー承認はまだない。既存の完全クリア後の画面フローを調査し、必要なら確認する。
- **「完全クリア」の正確な判定条件**：既存の開拓・施設完了判定を再利用し、新しい独自判定を安易に増やさない。
- **施設訪問数・自力／自動開拓の計数境界**：既存処理と重複・二重計上がないように定義する。特に開始地点とスキルによる初期自動開拓を区別する。
- **お宝の「失敗」**：お宝にも獲得失敗が存在することは確定。既存イベントで成否を取得できる箇所を調査する。
- **初獲得判定**：仲間・お宝それぞれ既存図鑑／所持履歴との整合を確認する。
- **特殊イベントやチュートリアルマップ**：通常マップと報酬・施設数が異なる場合も破綻しないこと。
- **問題数が0のケース、マップ中断・再開、保存容量**：実装・検証時に対応する。旧セーブ移行は必須ではない。

## 5. 技術設計の推奨

### 5.1 保存モデル

現在の冒険の一時集計と、確定済みの直近リザルトを分ける。

```js
// 構造イメージ。既存セーブ形式を確認し、名前や階層は合わせること。
currentAdventureStats: {
  elapsedActiveMs: 0,
  solved: 0,
  firstTryCorrect: 0,
  maxFirstTryStreak: 0,
  byOperation: {},
  exploration: { manualOpened: 0, automaticOpened: 0, revealed: 0, facilitiesVisited: 0 },
  encounters: [
    // { sequence, type: 'companion'|'treasure'|'reward', id,
    //   success, firstAcquired, source }
  ]
},
lastClearResult: {
  // 確定時点の統計、地図スナップショット、イベント履歴、完了識別子
}
```

- これは**実装の強制スキーマではない**。既存の保存・復元・バージョン移行処理を優先する。
- 各遭遇イベントは、発生順とその時点での成功／失敗・初獲得を確定して記録する。
- 完全クリア確定時にリザルトをスナップショット化し、再表示は進行中ワールドの状態に依存しないようにする。
- カウンタは「現在の累計値との差分」だけに依存すると、途中再開や既存セーブで崩れやすい。冒険単位で永続化することを推奨する。

### 5.2 既存実装の確認ポイント

検討時点で参照した情報では、累計正解数、累計開拓数、仲間加入の成功／失敗、施設集計、ワールドの報酬情報などは存在する一方、**冒険単位の初回正解・誤答・遭遇順・アクティブ時間を完全に保存する機能は未確認**だった。Workは最新版で以下を調査すること。

- 問題生成／解答処理：初回回答の判定、演算種別、連続正解の記録地点。
- マップ開拓／視界処理：自力開拓と自動開拓（スキルの初期自動開拓、追加開拓、博物館ボーナス）、透視の発生地点。
- 施設処理／加入／お宝獲得／全域開拓報酬：遭遇イベントの順序、成否、初獲得判定地点。
- 完全クリア処理：複数回呼び出しや再読込への耐性。
- ホーム「記録・実績」画面、保存／復元機構、バージョン管理。

## 7. 受け入れ基準

- [ ] 完全クリア時に一度だけ祝福リザルトが自動表示される。
- [ ] 全域開拓だけで未訪問施設が残る場合は表示されない。
- [ ] 問題数・初回正解率・最大連続正解・演算別成績が正しく計測される。
- [ ] 開拓実績は**自力／自動の2分類のみ**。初期スキル開拓・博物館ボーナスは自動に入り、二重計上しない。
- [ ] 透視と施設訪問数が正しく記録される。
- [ ] クリアした実際の地形と施設位置をミニマップに表示できる。
- [ ] 仲間・お宝・報酬が一つのカードに遭遇順で並ぶ。
- [ ] 失敗はグレー＋赤い×、初獲得は王冠、重複遭遇は個別表示になる。
- [ ] 全域開拓報酬の仲間が思い出に含まれ、**報酬を受け取った後**にリザルトが出る。
- [ ] 放置時間は含み、ホームなど冒険以外の画面・バックグラウンド・終了中は除くプレイ時間を保持する。
- [ ] 直近リザルトが「記録・実績」から再表示でき、新しいクリアでのみ上書きされる。
- [ ] 旧セーブを初期化する／次の冒険から計測する等の移行方針が事前報告され、通常の冒険進行を壊さない。
- [ ] 未決定の画面遷移は既存フローとの整合を確認してから確定する。

## 9. ver.75 実装・承認済み補足

ユーザーが事前案を承認：閉じると同じ冒険マップへ戻る（新規出発や帰還は強制しない）。報酬カード・既存チュートリアルを閉じてから表示する。旧セーブを削除せず、次の新しい冒険から計測し、既存ワールドの履歴は推測しない。第1/第2チュートリアルも新規生成分から対象。

- common/result.jsが計測・確定、result-ui.js/result.cssが共通表示。world.adventureStatsとsave.lastClearResultを分離する。schemaVersion/keyは維持。新規冒険でも直近結果を保持。
- 算数は正解・開拓の保存成功時に1問。pending.wrongから初回成否を判定。演算別add/sub/mul/div、初回正解の連続最大を保存。中止した未完了問題やリロードで消えた問題は問題数に含めない。
- 基本開拓1マスは自力。追加分と出発時A11/博物館/付随A03は自動。開始拠点は除外。透視は既存achievementVisionCount（新規透視累計）、施設数は保存済み訪問配列と施設配列から確定。
- events.resolveの確定結果を1回だけ記録。D07は最終結果、C03追加品は主対象の直後。progress.rewardの全域報酬も実受領順に記録。初獲得は実在庫更新前の値による。
- performance.nowの差分だけを加算。冒険ページがvisibleの間を計測し、5秒ごと・進行保存・visibilitychange/pagehideで保存。pageshowで再開。隠れていた時間や別ページ/終了中を跨ぐ時刻は保存しない。完全クリア成立のトランザクションで停止・スナップショット化。保存失敗は進行/報酬/リザルトを一括で取り消す。OS強制終了等でイベントが発火しないと直近チェックポイント以降（通常最大約5秒）は未保存となり得る。
- 完全クリア定義はBoukenProgress.statusを再利用。world.completionRecordedとstats.finishedで重複確定を防止。resultPendingを保存して、既存dialog/チュートリアル終了後に一度だけ自動表示する。表示済み保存が失敗したら自動表示せず再試行できる。
- 記録・実績の「直近のぼうけんを見る」は現在の世界でなく完了スナップショットを表示する。閉じると記録画面へ戻る。
- ミニマップは地形色＋赤い施設点。正方形セル/縦横比保持。思い出は単一カード、失敗はグレー画像＋赤い×、初獲得は王冠。0問の率は—。
