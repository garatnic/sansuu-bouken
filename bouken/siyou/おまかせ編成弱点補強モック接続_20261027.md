## 候補生成

新しい `integration/balanced-light.js`（UMD、Node/Worker共用）を追加。固定仲間を最初から含み、固定位置をA.arrangeで保持。固定0人の最初は4分野一様抽選、その分野の未固定所有の上位10人から一様抽選。既存O.estimatorによる `estimate(固定＋id)[分野] - estimate(固定)[分野]` で所有仲間の順位を作る。これは前回専門4モードの専門貢献スコアと同じ。個人式、スキル、冒険方策は変更しない。

仲間追加のたび編成全体の軽量推定を再計算。無作為基準編成の同じ推定値の平均を分野別proxy基準Rとし、`z[k] = max(0, estimate(編成)[k]) / max(0.000001, R[k])`、`weight[k] = 1 / (0.25 + z[k])`、`P[k] = weight[k] / sum(weight)` で補強分野を抽選する。逆数は弱い分野ほど単調に確率が上がり、0.25でゼロ時の無限大を避ける簡潔な試作定数。強い分野の確率も0にはしない。分野選択後、順位表から採用済みを除いて先頭10人を抽選対象とするので、採用済み上位を飛ばして次順位へ拡張する。1〜5枠対応、必ず4分野から1人ずつではない。

ID集合の重複を除外。最大1,000生成試行で50組に達しない小さい空間（全組合せ10,000以下）では次順位を含む採用可能集合を列挙して不足を補う。最大50、組合せ総数未満の水増しなし。大きい空間で上限に達したら理由を返す。生成は冒険を呼ばない。中断チェックとyieldを入れる。

最終順位は数値総合点の降順。上位10組、1位を最初に表示。完全同点の中のみ既存abilityDistanceで異なる能力を優先し、数値順位は変更しない。ほぼ同能力の組が残る可能性はあるため、ID種類数と能力signature種類数を別々に記録する。既存専門4モードの選び方はそのまま。

## 総合評価・基準と安全策

候補1組3回、最大50組=150論理試行。既存A.evaluator/O.adventureと同じ30問・map・所有/所持品/進行/スキル/固定制約。成果は opened / newItems / newCharacters / visited の平均。

- 無作為**12編成×2冒険=24論理試行**で分野ごとの実成果平均を得る。所有、枠、固定ID/位置、所持品、進行、mapサイズ/30問/方策/targetGroup、基準seedが同条件のWorker内キャッシュ（上限8件）を再利用。初回候補150とは別枠、最大174論理冒険。能力等価signatureの既存キャッシュにより物理実行は少なくなる場合がある。
- 参照の編成seed `referencePartySeed=26253001`、冒険seed `26252001,26252002`。推薦選抜seed `26251001..26251003` とは分離。無作為基準は固定を無視した全体平均ではない。基準にした12編成は診断結果内に保持するがセーブやlocalStorageには保存しない。
- 実成果基準の下限は開拓1マス、他3分野は **1/24種類・施設**。後者は参照24冒険で1件分という単位に由来する。偶然全ゼロ/極小値で割り算が壊れたり比が無制限に発散するのを防ぐ。測定平均/下限/採用分母をすべて返す。これは精密な母平均推定ではなく、希少成果時に正規化が不安定になる限界は残る。
- `点[k] = 候補3回の実平均[k] / max(基準平均[k], 下限[k]) * 100`。
- `平均 = sum(点)/4`、`最低 = min(点)`、`ペナルティ = 0.2 * max(0,100-最低)`、`総合点 = 平均 - ペナルティ`。係数0.2はsettings.penaltyに分離。例A=103、B=104をテスト。
- 候補の希少成果ゼロに対する足切り/失格/除外はしない。減点は最大20点に限るので偶然ゼロだけで自動排除しない。一方、0.2では弱い分野を持つ候補が残ることもあり、品質保証ではない。候補実成果の疑似加算・後付けの式調整は行わない。
- 完全収集時は既存outcomes.jsの評価専用仮定（在庫だけ未収集相当、取得済み博物館効果維持）を参照・候補・軽量推定すべてに適用。原セーブ非変更。
- この尺度は**おまかせ候補順位専用**。レーダー表示上限55/1.5/1.5/5、表示の開拓力、旧総合表示/他モードの式は変更しない。

## UIと復旧

Workerのbalancedだけ新モジュールへroute。専門4モードはPartyLight、randomは画面のA.randomOtherのまま。requestId/mode/context/候補一致ガード、キャンセルのWorker破棄、保存禁止、画像Mapキャッシュは維持。新おまかせも専門4モードと同じ保存10候補の順番巡回を使用する。

「ほかのおすすめ」は生成/150冒険/参照24冒険を再実行しない。表示用共通比較APIの現行編成24＋候補24seedだけを実行（能力等価ならキャッシュあり）。この比較平均は候補選抜の3回とは別で、表示値は3回平均と一致する必要はない。表示パーティーと比較対象IDの一致は検査する。固定/サイズ/モード変更で銀行を無効化、固定条件変更なら新生成。基準も条件一致時だけ再利用。中止後のWorker内基準は破棄される。

復旧：旧api.jsのrecommendManyをそのまま保持。Workerへのrecommend設定に `legacyBalanced:true` を渡すと旧経路、既存のchooseLegacyCandidateも残す。通常UIに復旧スイッチは増設しない。必要なときはworker.jsのbalanced分岐を旧API経路へ変更し、Worker/appのrevisionを更新してコミットする。専門4モード/ゲームコードの巻戻しは不要。
