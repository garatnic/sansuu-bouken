## 0. この仕様書の読み方

- **確定方針**：会話で採用された内容。四則演算を各25%、演算内パターンを均等、割り算「あまりなし：あり＝3：1」、4択、数百問の連続出題、簡単な反復問題も残す。
- **推奨初期値**：実装のために決める必要があるが、会話で細部まで確定していない内容。変更可能な設定として実装する。
- **原典との関係**：以前の「クアトロ・スピード」（四則演算のランダム出題）と「くりあがり・くりさがり けいさんゲーム」（全問列挙）の問題生成アイデアを統合し、今回の会話で拡張した仕様。原典コードの忠実な再現を目的としない。

## 1. 目的と非目的

### 1.1 目的

1. 何百問でも連続して、暗算でサクサク解ける四則演算の4択問題を返す。
2. 基本問題（例：2＋3、2×2）も反復学習に有効なので除外しない。
3. 極端な難問は出さず、足し算は最大99＋99、引き算は最大3桁−2桁、掛け算は0〜10の段、割り算は商1〜9・割る数2〜9・あまり最大8を基本上限とする。
4. 四則演算を**各25%**で満遍なく出題する。
5. 足し算・引き算は、**桁数と繰り上がり／繰り下がりのカテゴリ**を演算内部で均等に出題する。
6. 割り算の内部比率は**あまりなし75%：あまりあり25%**とする（3：1）。
7. 問題の候補を列挙してから抽選することで、全問列挙・無限出題の両方を単一エンジンで扱う。
8. 出題・選択肢生成と、ゲーム側の表示・操作・評価を分離する。

### 1.2 非目的

- ゲームのHP、ダメージ、戦闘、コンボ、制限時間、演出、得点、保存画面などは設計しない。
- 正答率や反応時間から難易度を自動変更しない。
- 難易度スコアに応じた複雑な出題比率調整をしない。
- 全問題の一律均等抽選はしない（演算やカテゴリの出題比率が崩れるため）。

## 2. 出題比率：階層型抽選

### 2.1 第1階層：四則演算

| 演算 | 抽選比率 |
|---|---:|
| 足し算（add） | 25% |
| 引き算（sub） | 25% |
| 掛け算（mul） | 25% |
| 割り算（div） | 25% |

### 2.2 第2階層：演算内部の分類

- 足し算：後述の**6カテゴリを等確率（各1/6）**。
- 引き算：後述の**9カテゴリを等確率（各1/9）**。
- 掛け算：カテゴリ分割なし。0〜10の全121式を候補にする。
- 割り算：**あまりなし75%、あまりあり25%**。

この結果、全体の理論比率は次のとおり。

| 分類 | 全体に占める割合 |
|---|---:|
| 足し算・各カテゴリ | 25% ÷ 6 ≒ 4.1667% |
| 引き算・各カテゴリ | 25% ÷ 9 ≒ 2.7778% |
| 掛け算全体 | 25% |
| 割り算・あまりなし | 18.75% |
| 割り算・あまりあり | 6.25% |

**重要：** 「カテゴリ間で等確率」と「個別の式が全体で等確率」は異なる。カテゴリ内の候補数に差があっても、カテゴリの抽選確率を変えない。カテゴリ内では候補式を均等に抽選する。

### 2.3 長期比率と短期の偏り

**推奨初期値：** 各階層に小さなシャッフルバッグを設け、短期間の偏りを抑える。

- 演算バッグ：`[add, sub, mul, div]` をシャッフルし、4回使い切ったら再シャッフル。
- 足し算カテゴリバッグ：6カテゴリを1回ずつ入れてシャッフルし、足し算が6回出たら再シャッフル。
- 引き算カテゴリバッグ：9カテゴリを同様に運用。
- 割り算タイプバッグ：`[exact, exact, exact, remainder]` をシャッフルし、割り算4回で再シャッフル。
- 各カテゴリの**問題バッグ**：候補式を全件シャッフルし、1周使い切ったら再シャッフル。

これなら長期比率だけでなく、例えば16問ごとに四則演算4問ずつ、割り算4問のうちあまりあり1問という安定感が得られる。ただし各バッグは独立して進むため、任意の連続16問に必ずこの構成が成立するとは限らない。バッグ境界をまたぐ区間では偏りが生じ得る。

**代替設定：** `selectionMode = "random"` として各階層を独立した重み付き乱数抽選にすることも可能。既定は `bag` を推奨。

## 3. 共通の問題表現・定義

### 3.1 桁数

- 1桁の正整数：1〜9。
- 2桁の正整数：10〜99。
- 3桁の正整数：100〜999。
- 掛け算に限り0と10を明示的に許可。
- 引き算は負数を生成しない。**答え0を許すか**は未合意のため、推奨初期値では**0以上**を許可する（`allowZeroSubtractionResult: true`）。正の答えのみとする設定も提供する。

### 3.2 繰り上がり（足し算）

- 1桁＋1桁／1桁＋2桁／2桁＋2桁について、**一の位同士の和が10以上**なら `carry=true`、そうでなければ `carry=false`。
- 2桁＋2桁では、十の位から百の位への繰り上がりだけが起きる場合もある（例：60＋50）。これは「一の位の繰り上がりなし」に分類する。**推奨初期値の分類は一の位基準**とし、百の位への繰り上がり有無は追加メタデータ `carryTensToHundreds` に記録する。
- 「どこかの桁で繰り上がりがあるか」をカテゴリ判定に使いたい場合は別設定が必要。本仕様では使わない。

### 3.3 繰り下がり（引き算）

- 引き算の筆算で、いずれかの桁において上の桁から借りる必要があれば `borrow=true`。
- 2桁−1桁、2桁−2桁では通常一の位の比較で判定可能。
- 3桁−1桁、3桁−2桁では、百の位から十の位への借り、ゼロをまたぐ連続した借りも含む。
- 実装では桁ごとに借りを伝播させて判定し、`borrowOnes`, `borrowTens`, `borrowCount` も記録する。負数を生成しないため、最上位桁で借り切れない問題は候補に入れない。
- 例：`123−57` は繰り下がりあり、`153−42` はなし、`100−99` は連続した繰り下がりあり。

### 3.4 問題ID

`operation:operand1:operand2` を基本とする（例：`add:7:8`）。

- `7＋8` と `8＋7` は**別問題**。
- `3×7` と `7×3` は**別問題**。
- 割り算は割られる数と割る数で識別する（例：`div:53:8`）。
- 同じ式を異なるカテゴリに重複登録しない。

## 4. 足し算の詳細仕様

### 4.1 候補範囲

- 1桁＋1桁：両項1〜9。
- 1桁＋2桁：一方1〜9、もう一方10〜99。表示順は両方許容する。
- 2桁＋2桁：両項10〜99。
- 最大式：`99＋99＝198`。
- 足し算では結果の上限を99に制限**しない**。
- 0を含む足し算は、今回の会話では明示されていないため推奨初期値では除外。

### 4.2 6カテゴリ

| ID | 桁数 | 一の位の繰り上がり | 例 |
|---|---|---|---|
| `ADD_1_1_NO_CARRY` | 1桁＋1桁 | なし | 3＋4 |
| `ADD_1_1_CARRY` | 1桁＋1桁 | あり | 7＋8 |
| `ADD_1_2_NO_CARRY` | 1桁＋2桁 | なし | 23＋4 |
| `ADD_1_2_CARRY` | 1桁＋2桁 | あり | 27＋8 |
| `ADD_2_2_NO_CARRY` | 2桁＋2桁 | なし | 34＋25 |
| `ADD_2_2_CARRY` | 2桁＋2桁 | あり | 68＋47 |

各カテゴリの抽選比率は足し算の中で1/6。1桁＋2桁の表示順は、候補式を両順で列挙するため、両方が同じ頻度になる。

### 4.3 注意点

- `60＋50` は百の位への繰り上がりがあるが、上記カテゴリでは `ADD_2_2_NO_CARRY`（一の位の繰り上がりなし）となる。
- これが直感に反する場合は、`carry` の定義を「どこかの桁で繰り上がる」に変更できる。ただし**カテゴリ分けと問題プールを作り直す必要がある**。

## 5. 引き算の詳細仕様

### 5.1 候補範囲

- 被減数（左辺第1項）：1〜999。
- 減数（左辺第2項）：1〜99。
- **3桁−3桁は出題しない**。
- 結果は原則0以上、負数なし。
- 3桁−1桁も許可（最大3桁−2桁の範囲内）。

### 5.2 9カテゴリ

| ID | 桁数 | 繰り下がり | 例 |
|---|---|---|---|
| `SUB_1_1_NO_BORROW` | 1桁−1桁 | なし | 8−3 |
| `SUB_2_1_NO_BORROW` | 2桁−1桁 | なし | 17−3 |
| `SUB_2_1_BORROW` | 2桁−1桁 | あり | 17−8 |
| `SUB_2_2_NO_BORROW` | 2桁−2桁 | なし | 74−32 |
| `SUB_2_2_BORROW` | 2桁−2桁 | あり | 83−47 |
| `SUB_3_1_NO_BORROW` | 3桁−1桁 | なし | 153−2 |
| `SUB_3_1_BORROW` | 3桁−1桁 | あり | 123−7 |
| `SUB_3_2_NO_BORROW` | 3桁−2桁 | なし | 153−42 |
| `SUB_3_2_BORROW` | 3桁−2桁 | あり | 123−57 |

**1桁−1桁の「繰り下がりあり」は成立しない**ため、カテゴリを作らない。全9カテゴリを引き算内で各1/9とする。

### 5.3 桁数・繰り下がりの判定

- 左右の桁数は**式の表示値そのもの**から判定する。
- 例：`100−99` は3桁−2桁、繰り下がりあり。
- `100−1` は3桁−1桁、繰り下がりあり。
- `10−10` は2桁−2桁、繰り下がりなし（結果0を許可する設定の場合）。

## 6. 掛け算の詳細仕様

- 第1項・第2項：それぞれ**0〜10の整数**。
- 全候補：11×11＝**121通り**（左右の順序を区別）。
- 最大の式：`10×10＝100`。
- 2桁同士の一般的な掛け算は出題しない。**10だけ例外として許可**。
- `0×7`、`7×0`、`2×2`、`7×8`、`10×9`、`10×10` はすべて対象。
- 121式を1つの問題プールとして扱い、各式を均等に取り出す。
- 0の段や10の段の比率を別途補正しない。

## 7. 割り算の詳細仕様

### 7.1 共通の生成式

`dividend = divisor × quotient + remainder`

- 割る数 `divisor`：2〜9。
- 商 `quotient`：1〜9。
- あまり `remainder`：0〜`divisor−1`。
- 割られる数 `dividend`：上式で逆算。
- 最大：`89÷9＝9 あまり8`。
- あまりは割る数より必ず小さい。
- 0除算、商0、負数、小数、分数は出題しない。

### 7.2 2つの問題プール

**あまりなし（`DIV_EXACT`）**

- `remainder = 0`。
- 割る数2〜9、商1〜9。
- 候補数：8×9＝**72通り**。
- 例：`42÷7＝6`、`81÷9＝9`。

**あまりあり（`DIV_REMAINDER`）**

- `1 ≤ remainder < divisor`。
- 割る数2〜9、商1〜9。
- 候補数：`9 × Σ(divisor−1), divisor=2..9`＝9×36＝**324通り**。
- 例：`53÷8＝6 あまり5`、`89÷9＝9 あまり8`。

**割り算の内部抽選：あまりなし75%、あまりあり25%。** 候補数72対324という違いで出題比率を決めてはいけない。

### 7.3 「九九の逆算」の範囲に関する注記

会話では「九九の逆算」「0の段と10の段まで」が挙げられたが、後者は掛け算に対する指定。割り算については、直前の合意に沿って**割る数2〜9、商1〜9**を推奨初期値とする。`0÷7`、`80÷10`、`7÷1` は初期設定では対象外。これらを含める拡張は可能だが、現時点で合意済みとは扱わない。

## 8. 候補プールの生成

### 8.1 基本方針

1. 起動時または設定変更時に、各カテゴリの全候補式を**決定的に列挙**する。
2. 式ごとに演算、項、答え、桁数、繰り上がり／繰り下がり、あまりの有無を計算する。
3. 分類条件に一致するカテゴリへ1回だけ登録する。
4. 同じ問題IDが同一プールに重複しないことを保証する。
5. 各カテゴリのプールをシャッフルして保持する。
6. 次の問題要求ごとに「演算 → 内部分類 → 式」の順に抽選する。
7. あるカテゴリのプールを使い切ったら、そのカテゴリだけ再シャッフルする。

### 8.2 候補数とメモリ

- 掛け算121、割り算396は固定。
- 足し算・引き算は数千〜数万件規模になり得るが、ブラウザ内で管理可能な想定。必要なら**各カテゴリの式を事前に数値ペア配列で保持**し、選択肢は出題時に生成する。
- **問題の全候補をグローバルに1つの袋へ入れない。** それでは四則演算・内部分類の比率が崩れる。

### 8.3 問題重複の意味

- **同一カテゴリ内では、1周使い切るまで同一の式を繰り返さない。**
- 各カテゴリの候補数は異なるため、候補が少ないカテゴリほど同じ式が再登場する頻度が高くなる。これはカテゴリ出題比率を守るための意図した挙動。
- シャッフルバッグの境界では、直前と直後に同一問題が出る可能性がある。**推奨初期値：直前と同じ問題IDなら新しい周の先頭と交換して連続重複を回避する**（候補数1の場合は例外）。

## 9. 4択選択肢の生成

### 9.1 必須条件（確定方針）

- 常に4択：正解1個、不正解3個。
- 選択肢はすべて異なる。
- 表示順は毎問ランダムにシャッフル。
- 数値として正しい答えと同じ誤答は入れない。
- 割り算の答えは商とあまりを組み合わせた**構造化データ**として扱い、単なる文字列比較に依存しない。

### 9.2 推奨初期値：誤答の作り方

**足し算・引き算・掛け算**

1. 正解に近い整数を優先する。候補オフセット：`[-10, -2, -1, +1, +2, +10]`。
2. 正解・既存選択肢と重複する値は除外。
3. **負の誤答は除外**。0は正解または自然な誤答として許可（0の段・引き算に対応）。
4. 3個足りなければ、正解から±3〜±15の範囲で追加抽選する。
5. それでも不足したら非負整数の探索範囲を広げ、必ず4個を確保する。

**割り算**

1. 正解の商を±1した値（商0未満は除外）。
2. あまりを±1した値（0以上かつ割る数未満）。
3. 商とあまりの組み合わせを変えた値。
4. **すべての選択肢で `0 ≤ あまり < 割る数` を守る**。原典Aにあった「あまりが割る数以上」の誤答は採用しない。
5. あまりなし問題では、原則として整数の商だけを選択肢にする。あまりあり問題では `商 あまり あまり値` の形式で揃える。これは表示の一貫性を優先した**推奨初期値**であり、変更可能。
6. 正解と誤答の構造化データを比較し、重複がない4択を生成する。

**注意：** 誤答生成の具体的なオフセット・表示統一ルールは今回新たに補った推奨初期値。既存ゲームの誤答ロジックをそのままコピーしたものではない。

### 9.3 4択生成の堅牢性

- 候補生成の試行回数に上限を設ける（例：30回）。
- 上限後は決定的な列挙で不足分を埋め、無限ループを防止する。
- 不正解を選んだ場合のUI挙動はエンジンの責務外。

## 10. 現行エンジンAPI

### 10.1 実装済みインターフェース

`BoukenMath.create(config)`の有効設定はselectionMode、allowZeroSubtractionResult、avoidImmediateRepeatの3つ。四則各25%、割り算3:1、選択肢4個は固定で、旧API案のoperationWeights/divisionExactWeight/divisionRemainderWeight/choiceCountは有効な変更設定ではない。getConfigが返す任意追加キーを、処理が適用していると誤認しない。formatAnswer(answer)も公開する。

```ts
type Operation = 'add' | 'sub' | 'mul' | 'div';
type SelectionMode = 'bag' | 'random';

type MathEngineConfig = {
  selectionMode: SelectionMode;                 // 既定: 'bag'
  allowZeroSubtractionResult: boolean;          // 推奨: true
  avoidImmediateRepeat: boolean;                // 推奨: true
};

type Answer = {
  quotientOrValue: number;
  remainder?: number; // div のときのみ。あまりなしなら0
};

type MathQuestion = {
  id: string;
  operation: Operation;
  category: string;
  operand1: number;
  operand2: number;
  prompt: string;
  answer: Answer;
  choices: Answer[];
  correctChoiceIndex: number; // 0..3
  metadata: {
    hasCarry: boolean;
    hasBorrow: boolean;
    borrowCount?: number;
    hasRemainder: boolean;
  };
};

interface MathQuestionEngine {
  nextQuestion(): MathQuestion;
  reset(): void;
  getConfig(): MathEngineConfig;
  getPoolStats(): Record<string, number>;
}
```

- `reset()` はバッグの位置と直前出題履歴を初期化し、次の抽選から各バッグを再生成する。
- ゲーム側は `prompt` と `choices` を描画し、選択したインデックスが `correctChoiceIndex` と一致するか判定できる。
- `answer` は表示文字列ではなく数値構造として返す。
- エンジンは問題の正誤履歴・プレイ記録・制限時間を持たない。

## 11. 擬似コード

```text
initialize(config):
    pools = enumerateAndClassifyAllQuestions(config)
    assert every required category has >= 1 question
    operationBag = shuffled([add, sub, mul, div])
    addCategoryBag = shuffled(6 add categories)
    subCategoryBag = shuffled(9 sub categories)
    divisionTypeBag = shuffled([exact, exact, exact, remainder])
    for each category: questionBag[category] = shuffled(pools[category])

nextQuestion():
    op = drawOperation(operationBag or weightedRandom)
    if op == add: category = draw(addCategoryBag)
    if op == sub: category = draw(subCategoryBag)
    if op == mul: category = MUL_ALL
    if op == div: category = draw(divisionTypeBag)
    q = draw(questionBag[category])
    if avoidImmediateRepeat and q.id == previousQuestionId:
        swapWithDifferentCandidateIfAvailable(questionBag[category])
    choices = generateFourDistinctChoices(q)
    shuffle(choices)
    previousQuestionId = q.id
    return formatQuestion(q, choices)
```

`selectionMode='random'` の場合は、カテゴリ選択と問題選択の両方で重み付き／一様乱数抽選を使用する。**ただし四則演算25%、足し算6カテゴリ均等、引き算9カテゴリ均等、割り算3：1の重みは維持**する。

## 14. 最終要約：他プロジェクトに渡す際の必須事項

**四則演算問題生成専用の独立エンジンを作る。四則演算は各25%。足し算は1桁＋1桁、1桁＋2桁、2桁＋2桁の各々を一の位の繰り上がり有無で分けた6カテゴリを均等出題し、最大99＋99まで。引き算は1桁−1桁、2桁−1桁、2桁−2桁、3桁−1桁、3桁−2桁を繰り下がり有無で分類した実現可能な9カテゴリを均等出題し、負数と3桁−3桁を除外。掛け算は0〜10の段の121式。割り算は割る数2〜9、商1〜9、あまり0〜割る数−1、最大89÷9＝9あまり8。割り算内部の比率はあまりなし3：あり1。カテゴリごとの全候補を列挙し、階層型シャッフルバッグで取り出す。4択は正解1個＋異なる誤答3個。ゲーム固有の戦闘・ダメージ・タイマー等は一切実装しない。**
