# おすすめパーティー・独立操作モック

ゲーム版69、開始時main `dfc733ff21dddc2bed9fb4041b05afc9f9e2804c`を確認して作成。推薦品質の検証ではなく、画面/固定/再提案/決定/キャンセルの体験を確認する。

入口：[index.html](index.html)。スマホ縦画面を優先。第1/第2段階エンジンもゲーム本体も変更しない。

## 操作

- タイプ5種類は場所を取りすぎないドロップダウン。
- 仲間の大きいカードをタップすると固定/解除。金枠・鍵・aria-pressedで区別。下の「スキル」は別操作で既存の詳細ダイアログを開く。
- 固定の管理キーは仲間ID。モックでは見失わないよう元の表示位置も維持する。既存編成は順序を持ち、チュートリアル第2出発の先頭枠確認にも意味があるため勝手に並べ替えない。
- 「ほかのおすすめ」は固定以外の枠だけを入れ替える。集合として直前と同じ編成を除外し、同じ仲間を二重に入れない。順番だけ変えるものを別候補と数えない。
- 以前の集合は可能な限り避ける。候補を一巡したら案内して履歴を周回し、直前と異なる候補へ進む。他候補がない/全員固定は別メッセージで説明する。
- タイプ変更でもIDと固定位置を引き継ぐ。人数/候補数のテスト条件変更だけは案内どおり初期化する。
- 決定はモックの確認ダイアログだけ。実際の編成も、比較用の最初の編成も書き換えない。
- 「もどる」はモック内の最初の編成表示へ戻り、固定と候補履歴をリセット。「もういちどためす」で再開。ゲームページへ遷移しない。

## データ・画像

samples.jsonは開始時mainのcharacters/skills/skill_messagesから24体と関係するスキルをそのまま抜粋したスナップショット。名前・ID・実スキルは実データだが、所持状態/現在編成/タイプ別候補はサンプルである。

候補はタイプ別に用意した順序のローテーションと固定IDのマージ。実エンジン、成功率計算、性能保証、最強ランキングはない。理由は「サンプル」と表示し、実際に持つスキル系統の存在だけを説明する。D04を有効な効果として案内しない。

既存common/character-images.jsを再利用。同じcharacter_sheet.pngをdocument内1回だけ初期化し、表示用64px CanvasもIDごとに保持して使う。候補/固定/タイプを変更してもPNGを再取得しない。common/character-detail.js/.cssへ実データを渡して詳細表示する。相対パスが固定されているskill-ui.js、save.js、master.js等は読み込まない。

画像待ちでも操作可能。画像が失敗したら人型マーク+実名で続行する。`index.html?images=fail`は非画像のunavailable-image.txtを1回読み、実際のImage.onerror経路を確認する専用条件。PNGは取得しない。`?images=off`も用意。開発欄の「画像なし」は表示だけを切替える。

## 保存非干渉

保存APIを呼ぶコードを持たない。さらにguard.jsがこのモックのwindowだけでlocalStorage/sessionStorage/indexedDBへのアクセスを拒否する。実ストレージのgetterも値も読まず、原データを書き換えない。決定・戻る・閉じる・リロード後にも保存する状態はない。開発欄のblockedStorageAttemptsで意図しないアクセスを検出する。ゲームを開いている別タブには影響しない。

## テスト条件

開発用折りたたみ欄で1～5人（特に2/3/5人）と「たっぷり/少ない/ひと組だけ」を変更できる。これは枠の解放状況を模擬するだけで、実際の所持数や容量を変更しない。正式接続時は既存のcapacity/所有ID/正規化を使う。

```sh
node bouken/tests/party-recommendation/mock/test.cjs
```

11項目の決定的テストと3,000回の混合操作。複数ID/位置固定、解除、5タイプ、循環、候補なし、重複防止、1～5枠、保存ガードを検査する。

responsive.htmlは320/390/412/800pxのCSS幅を点検するためのiframeで、実機のタッチ/CPU/メモリ/電池を再現しない。公開クラウドChromeの結果はverification.jsonへ追記する。スマホ実機はユーザー確認待ち。

## 正式接続時の注意

- 固定IDを必須制約として実エンジンへ渡し、非固定枠から同IDを除外する。
- 現在編成と提案を分離し、正式な保存は既存保存処理の成功時だけ確定する。
- 全員固定/所有不足/候補切れ/未解放枠と、タイプ変更時の固定維持を守る。
- サンプル用順序/テスト所有/保存ガードを本番ゲームへコピーしない。
- 評価エンジンの品質残件は第2段階報告のまま。今回のモック受入を推薦精度の合格としない。
- 本体への組込みはユーザーのモック評価後、別工程で判断する。
