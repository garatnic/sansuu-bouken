入力基準：main `9a9a718266d792337edef7b48f2227049e3be7ae`、ゲームver.74、理論採点仕様 `1.0.0-draft`。Phase 3の整数絶対点927体×4分野をそのまま読み、相対指標を別ファイルへ保存する。本体や模擬冒険エンジンからは読み込まれない。

## 実行

リポジトリルートから以下を実行する。Node.js 18以上とPython 3の標準ライブラリのみ。検証環境はverification.jsonのnode欄。

```sh
node bouken/tests/character-aptitude/phase5a/analyze.cjs
node bouken/tests/character-aptitude/phase5a/verify.cjs
```

最初のコマンドはPhase 5AのCSV5点、analysis.json、REPORT.mdだけを上書きする。2番目は26テストを実行し、validation.logとverification.jsonを更新する。失敗時は非0終了。生成物は同じ入力でバイト単位に再現する。検証ログの実行時間は変動する。

source-manifest.jsonには調査元mainコミットと、既存Phase 3/4全ファイル、version.js、characters.json、skills.json、採点v1仕様のSHA-256を保存する。不一致なら停止する。manifestを無条件更新して不一致を隠さない。

## 計算定義

- 分野ごとに927体を母集団とする。標準偏差は分母927。絶対点は保存済みPhase 3の0〜100整数で、raw再採点や丸め直しは行わない。
- 偏差値＝50＋10×(絶対点−分野平均)/母標準偏差。標準偏差0なら全員50。0〜100への制限はしない。
- パーセンタイル＝100×(昇順の同点平均順位−1)/(N−1)。N=1なら50。同点は全員同じ値。欠落得点にはpercentileや順位を作らない。
- 分野内順位はcompetition方式（1,1,3）。`rank=rankStart=厳密に高い人数+1`、`rankEnd=厳密に高い人数+同点人数`、`rankMid=(rankStart+rankEnd)/2`。出力のID順に順位上の意味はない。
- `topPercent=100×rankMid/N`。`topPercentStart/End=100×rankStart/End÷N`を同時保存する。端点基準がNとN−1で異なるので、topPercentは100−percentileとは別の値。単独1位なら上位100/927%、最低集団の末尾は上位100%。同点の個体はグループ内のどこにあるとも決めず、範囲として読む。
- 全員同点なら偏差値50・percentile50・順位1〜N。上位割合は人数割合として(1〜N)/Nなので平均位置は50+50/N%。単一人ならtopPercent100%、percentile50。これは定義の境界テストで、実データはN=927。
- 得意判定は各方式の最大値を持つ全分野。絶対点の整数同値を全保持し、相対値の浮動小数誤差は絶対許容1e−12とする。表示用丸めを判定に使わない。
- 複数分野間の絶対点比較は今回の比較対象の一方式であり、正式な得意分野ルールとして採用していない。最低点による足切り・0点排除・恣意的なタイブレークを設けない。

## 候補抽出と解釈

候補ルールはanalysis.jsonに固定して説明する。判定方式の不一致、percentileと絶対点の見かけの差50以上、絶対30以下かつpercentile80以上、相対最大分野の同点93人以上、raw0の相対最大、相対最大がE/D06支援のみから生じるケースを抽出する。これらは表示解釈の診断であり、候補以外を適性対象から排除する最低点ルールではない。低絶対点の「高い相対評価」は境界70/80/90の件数も併記し、閾値依存を開示する。

異なる尺度の差を予測誤差として扱わない。スキルとの違和感はv1寄与の内訳から説明し、職業・種族・名前の印象を採点根拠にしない。再検査候補は数値の不正が見つかった体数ではない。0寄与で相対最大となる例を含め、表示方式や得意判定をChatとユーザーで相談するための一覧。

Phase 4の結果は927体の変換確定後に結合する。実測値を係数の決定へ使わない。単調変換では分野内の同点と順位が維持され、Spearmanは変わらない。Pearsonは偏差値で不変、percentileで変化し得るが、これだけで精度改善と主張しない。

## 検証範囲

独立Python検算は927×4×11＝40,788の指標比較と927×3＝2,781の最大集合比較。26のNodeテストは同点・ゼロ分散・単一人・入力順・表示丸め・相関・診断全件・CSV・再生成と既存ファイル保護を含む。今回、Phase 4のpilot/run/validateは実行しない（リプレイも追加実測となるため）。Phase 6未使用群の理論値は母集団に含むが、新しい実測には使用しない。
